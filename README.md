# 名刺人脈検索システム 導入手順

スマホから「会社名・氏名・住所・業種・役職」で名刺を検索できる、非公開のWebアプリです。
**個人情報はGoogleの非公開スプレッドシートにのみ保存**し、公開領域（GitHub等）には一切置きません。
アクセスは**Googleログインの内側に限定**されます（自分のアカウントのみ）。

---

## 構成（$150のPlaces APIは不使用・実質無料）

```
[スマホ] ── Googleログイン ──> [GAS Web App(UI/検索API)] ──> [非公開スプレッドシート(名刺DB)]
```

- データ層：Google スプレッドシート「名刺DB」（限定共有・自分のみ）
- API/UI層：GAS HtmlService（このコード）。デプロイ設定で「自分のみ」アクセス
- 都道府県・業種・役職レベルは**住所と会社名から無料で自動付与**済み

---

## セットアップ（初回・約10分）

### 1. スプレッドシートを作る
1. Google ドライブで新規スプレッドシートを作成し、名前を「名刺DB」等にする
2. シート名（タブ）を **`名刺DB`** に変更する
3. メニュー **ファイル > インポート** から `名刺DB_初期データ.csv` を読み込む
   - インポート場所：**現在のシートを置き換える**
   - 区切り文字：**カンマ**　／　1行目が見出しになっていればOK
   - ※3,799件・先頭行が `id, 会社名, 部署名 …` の見出し

### 2. スクリプトを入れる
1. スプレッドシートのメニュー **拡張機能 > Apps Script** を開く
2. 既定の `コード.gs` の中身を、本フォルダの **`Code.gs`** で置き換える
3. 左の「＋」から **HTML** ファイルを追加し、名前を **`Index`** にして
   **`Index.html`** の中身を貼り付ける（ファイル名は拡張子なしで `Index`）
4. 保存

> clasp派の場合：`appsscript.json`＋`Code.gs`＋`Index.html` をそのまま `clasp push`。

### 3. Webアプリとして公開（自分だけがアクセス）
1. Apps Script 右上 **デプロイ > 新しいデプロイ**
2. 種類：**ウェブアプリ**
3. 次のユーザーとして実行：**自分**
4. アクセスできるユーザー：**自分のみ**　←ここがセキュリティの肝
5. デプロイ → 表示されたURLがアプリのURL

### 4. スマホで使う
1. スマホのブラウザで、上記URLを開く（**そのGoogleアカウントでログイン**しておく）
2. ブラウザの共有メニューから **ホーム画面に追加** → アプリのように起動できる

## 今後、残り約2,500件を追加する方法

毎回CSVを整形し直す必要はありません。**名寄せして自動追記**されます。

1. Eightから新しいCSVをダウンロード
2. そのCSVを Google ドライブにアップロードし、**ファイルID**を控える
   （ファイルを開いたURL `…/d/＜ここがファイルID＞/view` の部分）
3. スプレッドシートのメニュー **名刺DB > Eight CSVを取り込む（名寄せ追記）** を実行
4. ファイルIDを貼り付けてOK
   → 既存と重複する人（会社名＋姓＋名が同じ）は自動スキップ、新規だけ追加

※ Eightの元CSV（Shift_JIS）のまま取り込めます。都道府県・業種・役職レベルも取込時に自動付与されます。

## アクセス権を複数アカウントにしたい場合

`Code.gs` 冒頭の `ALLOWLIST` に許可メールを列挙し、デプロイの「アクセスできるユーザー」を
**全員（ただしGoogleアカウント必須）** にすると、リストのアカウントだけが使えます。
通常は「自分のみ」が最も安全です。

## よくある調整

- **検索の最大表示件数**：`Code.gs` の `RESULT_LIMIT`（既定200）
- **フリーワードの対象列**：`searchCards` 内の `fields` 配列
- **業種の精度を上げたい**：現在は会社名のキーワード判定（無料）。将来Claude Haikuで
  分類し直せば「その他」を大幅に減らせます（4,000件でも数百円規模）

---

## セキュリティ要点

- 公開リポジトリ等に**個人情報・APIキーを置かない**（このアプリはGoogle内部で完結）
- Webアプリは必ず「**自分のみ**」または許可リストでデプロイ
- 検索結果は条件に一致した分だけ返却（全件を一括公開しない）

## CRM 機能（2026-09 追加）：新着整理・交換情報の一括設定・SNS確認

検索画面（GitHub Pages）にログインすると、トップに「新着名刺」「未整理」「要フォロー」の入口が出ます。
「要フォロー」は 次回アクション日が今日以前の人、タグ「要フォロー」を付けた人、または接触履歴で「要フォロー」にチェックしフォロー日が今日以前の人です。
整理モードのクイックタグは初期12件に加え、過去に自由入力したタグも候補に出ます。
データはすべて非公開スプレッドシート「名刺人脈DB」の3シート（`名刺DB` / `人物管理` / `接触履歴`）に保存されます。
詳細な列・API 一覧とロールバック手順は `docs/ADD-SNS-BULK-NOTES.md`、要件は `docs/CRM-ADD-SNS-BULK.md`。

### 交流会後の基本の流れ

1. 名刺をスキャン（または Eight CSV 取込）→ 15分以内に `名刺DB` に追記される（スキャン取込では名刺交換日は空欄。交換日は次の一括設定で入れます）
2. トップ「新着名刺」を開く（既定は過去7日。今日／3日／30日に切替可）
3. **「交換情報を一括設定」** で交換日とイベント名をまとめて登録（下記）
4. **「整理を始める」** で未整理の人物を 1 人ずつ確認。何も入力せず「次へ」でも進めます
5. 必要な人だけ タグ・重要度・次回アクション・メモ を付けて「保存して次へ」（自動的に整理済みになります）
6. 重要人物だけ「SNSを探す」で SNS アカウントを確認・保存

### 交換情報の一括設定（1件ずつ入力しない）

1. 新着名刺画面 → 「交換情報を一括設定」
2. 交換日（既定は今日）とイベント名（過去に使った名前は候補に出ます。例: `守成 青山デイライト`）を入力
3. 対象を選ぶ: **今回取込全件**（表示中の期間の全員）／**未設定のみ**（名刺交換日が空の人だけ）／**チェックした人物**
4. 「対象を確認」→「N件に設定します（うち上書き対象 M件、履歴作成済み K件）」を確認して「適用」
   - 名刺交換日が既に入っている人は**上書きしません**。上書き対象がある場合だけ「上書きしますか？」と聞かれます
   - 各人に接触履歴（種類 `名刺交換`、イベント名、交換日）が作られます。同じ内容の履歴が既にある人は**重複作成されません**（2回押しても安全）
5. 人物詳細には `守成 青山デイライト 260908` のように「イベント名 YYMMDD」で表示されます（内部の保存は `2026-09-08` 形式）
6. 検索画面のイベント名チップ／イベント名欄で「そのイベントで会った人」を後から検索できます

### SNS 確認（候補は確定するまで保存されません）

1. 人物詳細 または 新着リストの「SNS」から SNS確認画面へ
2. **公式サイトから検出**: 名刺の会社 URL のページ内にある Facebook / Instagram / LinkedIn / X / YouTube リンクを候補表示。
   本人のものと確認できたら「このアカウントで確定」。会社公式・店舗アカウントの可能性があるので必ず目で確認してください
3. **手動で登録**: プロフィール URL（`https://` 必須。各 SNS のドメインのみ受け付け）を貼って「確定」
4. **検索して探す**: 「氏名 会社名」を入れた Google 検索／各 SNS 内検索を新しいタブで開き、見つかった URL を手動登録
5. 確定済みは人物詳細にボタン表示（タップで開く）。「解除」で消せます。1 つでも確定すると「SNS確認済み」バッジが付きます
6. 探しても見つからなかった人は「候補なしで確認済みにする」で確認済みにできます（URL は保存されません）

### 初期表示について

ログイン直後の画面（入口の件数・検索条件・新着一覧）は `bootstrap` 1回で取得し、GAS 側で 120 秒キャッシュします。
保存・一括設定などの書き込みを行うとキャッシュは即座に消えるので、整理直後に古い件数が出ることはありません。
別端末やスプレッドシート直接編集の反映は最大 2 分遅れることがあります（新着画面の期間チップを押し直すと最新を取得します）。

### スプレッドシート側の注意

- `名刺DB` の既存列は変更していません。末尾に `importBatchId` が追加されます
- `人物管理` と `接触履歴` は初回の列セットアップ（`setupSnsBulkColumns_`）で自動作成されます。列を削除・並べ替えしないでください

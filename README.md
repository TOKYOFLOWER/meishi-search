# 名刺人脈検索システム 導入・運用手順

スマホ・PCから「会社名・氏名・住所・業種・役職」で名刺を検索できる、非公開データのWebアプリです。
**個人情報はGoogleの非公開スプレッドシートと非公開のDriveフォルダにのみ保存**し、公開領域（GitHub等）には一切置きません。
公開されているのは画面のガワ（`index.html`）だけで、データは認証を通った通信でのみ取得できます。

---

## 構成（$150のPlaces APIは不使用・実質無料）

```
[スマホ/PC] ──> GitHub Pages（index.html。公開だが画面のガワのみ・データなし）
                 https://tokyoflower.github.io/meishi-search/
     │  fetch(POST)
     v
[GAS Web App（匿名公開エンドポイント）] ──> [非公開スプレッドシート（名刺DB等）]
                                         └─> [Drive 非公開フォルダ meishi-images（名刺画像）]
```

- 画面層：GitHub Pages の `index.html`（HTML/CSS/JSのみ。個人情報・パスワード・キーは含まない）
- API層：GAS Web App（`src/Code.js`）。`src/appsscript.json` の `webapp.access` は **`ANYONE_ANONYMOUS`**、`executeAs` は `USER_DEPLOYING`（デプロイした自分の権限でシート／Driveを読み書き）
- データ層：非公開スプレッドシート（`名刺DB` / `人物管理` / `接触履歴` / `devices` など）と Drive の非公開フォルダ `meishi-images`
- 都道府県・業種・役職レベルは**住所と会社名から無料で自動付与**済み

### ANYONE_ANONYMOUS 前提のセキュリティ

GitHub Pages から別オリジンの GAS を呼ぶため、GAS Web App は匿名公開（`ANYONE_ANONYMOUS`）にしてあります。
つまり**エンドポイントURLは誰でも叩けます**。そのため、**すべての action（`ping` を含め認証なしで通るものは無い）をサーバー側（GAS）の認証で守る**設計です。画面側のログイン表示は認証の代わりになりません。
なお `doGet`（URLをブラウザで直接開いた場合）はデータを出さず、検索画面への案内だけを返します。

## 認証の仕組み

| 手段 | 使える action | 用途 |
|------|---------------|------|
| 端末トークン | 全 action | ブラウザ（スマホ/PC）。通常の通信はすべてこれ |
| ID/パスワード | `login`（と疎通確認の `ping`）のみ | 最初のログインで端末トークンを発行するためだけ |
| 取込専用キー `INGEST_KEY` | 取込系 action のみ（`addCard` / `attachImages` / `setThumb` / `cardsWithoutImage` / `cardsWithoutThumb` / `ping`） | `ingest/ingest.py`（スキャン取込） |

- **ID/パスワード**：GAS のスクリプトプロパティ `APP_USER` / `APP_PASS`。`login` で端末トークンを発行し、以後はトークンで通信します。**ブラウザにID/パスは保存しません**（入力した値は `login` リクエストの間だけメモリ／セッションに置き、成否にかかわらずすぐ破棄。localStorage に残るのはトークンのみ）。
- **端末トークン**：`devices` シートには**ハッシュだけ**を保存（トークン本体は端末のみ）。**最終利用から180日で失効**（使うたびに延長）。検証OKの結果は10分キャッシュされます。
- **取込専用キー `INGEST_KEY`**：`ingest.py` 用。GAS のスクリプトプロパティ `INGEST_KEY` と `ingest/.env` の `INGEST_KEY` に**同じ値**を入れます。取込系 action しか通らず、検索・閲覧・削除などは通りません。
  - **未設定の間は移行期間**として、ID/パスでも取込系 action が通ります。**設定後は ID/パスでは取込系 action は通らなくなります**（`login` / `ping` のみ）。
  - 設定手順：値を作る（例：`python -c "import secrets; print(secrets.token_hex(32))"`）→ GAS エディタ → 左の **プロジェクトの設定（歯車）** → **スクリプト プロパティ** → 「プロパティを追加」で名前 `INGEST_KEY`・値を入力して保存 → 同じ値を `ingest/.env` の `INGEST_KEY=` に書く（`ingest/.env` は git 管理外）。
- **ロックアウト**：ID/パスでの認証に**10回失敗すると15分間**、ID/パス認証をすべて拒否します（正しいパスワードでも）。端末トークンと `INGEST_KEY` は対象外です。画面には「試行回数が上限に達しました。15分後にお試しください」と出ます。
- GAS 内部の例外は応答に出さず（`server_error` のみ返す）、詳細は GAS 側のログに残します。

## セットアップ（初回）

### 1. スプレッドシートを作る
1. Google ドライブで新規スプレッドシートを作成し、名前を「名刺DB」等にする
2. シート名（タブ）を **`名刺DB`** に変更する
3. メニュー **ファイル > インポート** から `名刺DB_初期データ.csv`（`data/` フォルダ）を読み込む
   - インポート場所：**現在のシートを置き換える**
   - 区切り文字：**カンマ**　／　1行目が見出しになっていればOK

### 2. スクリプトを入れる（clasp）
1. スプレッドシートのメニュー **拡張機能 > Apps Script** でスクリプトを作成し、`.clasp.json` の `scriptId` をそのIDにする（`rootDir` は `src`）
2. スクリプトプロパティ（プロジェクトの設定 > スクリプト プロパティ）に `APP_USER` / `APP_PASS`（ログイン用）と、必要なら `INGEST_KEY`（上記）を設定する
3. 反映は下記「デプロイ手順」のとおり

### 3. Webアプリとして公開
1. Apps Script 右上 **デプロイ > 新しいデプロイ**（**初回のみ**）
2. 種類：**ウェブアプリ**
3. 次のユーザーとして実行：**自分**
4. アクセスできるユーザー：**全員**（`ANYONE_ANONYMOUS`。上記のとおり認証は全 action でサーバー側が行う）
5. 表示された Web アプリURLを `index.html` の `GAS_URL` に設定して GitHub Pages に公開する

### 4. スマホで使う
1. スマホのブラウザで GitHub Pages のURL（https://tokyoflower.github.io/meishi-search/）を開き、ID/パスワードでログイン（端末トークンが発行され、以後は自動ログイン）
2. ブラウザの共有メニューから **ホーム画面に追加** → アプリのように起動できる

## 運用手順

### 端末の失効（紛失・機種変更時）
スプレッドシートの **`devices` シート**で該当端末の行（`device_label` と `last_seen` で見分ける）の **`revoked` を `TRUE`** にします。
検証結果を10分キャッシュしているため、**反映まで最大10分**かかります。アプリの **ログアウト**でもその端末のトークンは失効します。

### ロック解除
ID/パスのロック（10回失敗）は、GAS エディタで関数 **`unlockPasswordLogin`** を選んで実行すると解除できます（何もしなくても15分で解除されます）。

### パスワード変更
スクリプトプロパティ `APP_PASS` を変更します。発行済みの端末トークンはそのまま有効です。**全端末を締め出したい場合**は、`devices` シートの `revoked` を全行 `TRUE` にします。

### デプロイ手順
```
clasp -u tokyoflower push
clasp -u tokyoflower version "<説明>"
clasp -u tokyoflower deploy -i <既存デプロイID> -V <バージョン番号>
```
**新規デプロイは作らない**でください（Web アプリのURLが変わり、`index.html` の `GAS_URL` と食い違います）。既存デプロイIDは `index.html` の `GAS_URL`（`/macros/s/＜デプロイID＞/exec`）に含まれるものです。

### 数式インジェクション対策の動作確認
GAS エディタで関数 **`testFormulaSafe`** を実行します。`=` `+` `-` `@` で始まる文字列を書いても数式にならないことを一時シートで確認し、結果（`ok` / `textFormatExact`）をログに出します（一時シートは自動で削除されます）。`ok` が `true` ならOKです。

## 今後、残り約2,500件を追加する方法

毎回CSVを整形し直す必要はありません。**名寄せして自動追記**されます。

1. Eightから新しいCSVをダウンロード
2. そのCSVを Google ドライブにアップロードし、**ファイルID**を控える
   （ファイルを開いたURL `…/d/＜ここがファイルID＞/view` の部分）
3. スプレッドシートのメニュー **名刺DB > Eight CSVを取り込む（名寄せ追記）** を実行
4. ファイルIDを貼り付けてOK
   → 既存と重複する人（会社名＋姓＋名が同じ）は自動スキップ、新規だけ追加

※ Eightの元CSV（Shift_JIS）のまま取り込めます。都道府県・業種・役職レベルも取込時に自動付与されます。

## セキュリティ要点

- 公開リポジトリに**個人情報・パスワード・キーを置かない**（`ingest/.env` は git 管理外。`.env.bak_*` も除外）
- 認証は全 action でサーバー側（GAS）が行う。ID/パスは `login` 専用で、ブラウザにはトークンのみ保存。ログイン失敗10回で15分ロック
- `index.html` に CSP（通信先は自身と GAS のみ）と `referrer: no-referrer` を設定
- 画像は登録済みの fileId（画像フォルダ内）だけを配信
- エラーの詳細は応答に出さず、GAS 側のログに残す
- シートへの書き込みは `safeCell_` を通し、数式として解釈されないようにする
- 検索結果は条件に一致した分だけ返却（全件を一括公開しない）

## CRM 機能（2026-09 追加）：新着整理・交換情報の一括設定・SNS確認

検索画面（GitHub Pages）にログインすると、トップに「新着名刺」「未整理」「要フォロー」の入口が出ます。
「要フォロー」は 次回アクション日が今日以前の人、タグ「要フォロー」を付けた人、または接触履歴で「要フォロー」にチェックしフォロー日が今日以前の人です。
整理モードのクイックタグは初期12件に加え、過去に自由入力したタグも候補に出ます。
データはすべて非公開スプレッドシート「名刺人脈DB」の3シート（`名刺DB` / `人物管理` / `接触履歴`）に保存されます。
詳細な列・API 一覧とロールバック手順は `docs/ADD-SNS-BULK-NOTES.md`、要件は `docs/CRM-ADD-SNS-BULK.md`。

## Eight風UI・永続ログイン（2026-09 追加）

端末トークンによる永続ログイン、listLite/listDelta による軽量一覧、一覧用サムネ配信を追加。
バックアップの所在とロールバック手順は `docs/EIGHT-UI-BACKUP.md` を参照。

### 交流会後の基本の流れ

1. 名刺をスキャン（または Eight CSV 取込）→ 15分以内に `名刺DB` に追記される（スキャン取込では名刺交換日は空欄。交換日は次の一括設定で入れます）
2. トップ「新着名刺」を開く（既定は過去7日。今日／3日／30日に切替可）
3. **「交換情報を一括設定」** で交換日とイベント名をまとめて登録（下記）
4. **「整理を始める」** で未整理の人物を 1 人ずつ確認。何も入力せず「次へ」でも進めます
5. 必要な人だけ タグ・重要度・次回アクション・メモ を付けて「保存して次へ」（自動的に整理済みになります）
6. 重要人物だけ「SNSを探す」で SNS アカウントを確認・保存

### 交換情報の一括設定（1件ずつ入力しない）

1. 新着名刺画面 → 「交換情報を一括設定」
2. 交換日（既定は今日）とイベント名（過去に使った名前は候補に出ます。例: `守成 青山デイライト`）を入力
3. 対象を選ぶ: **今回取込全件**（表示中の期間の全員）／**未設定のみ**（名刺交換日が空の人だけ）／**チェックした人物**
4. 「対象を確認」→「N件に設定します（うち上書き対象 M件、履歴作成済み K件）」を確認して「適用」
   - 名刺交換日が既に入っている人は**上書きしません**。上書き対象がある場合だけ「上書きしますか？」と聞かれます
   - 各人に接触履歴（種類 `名刺交換`、イベント名、交換日）が作られます。同じ内容の履歴が既にある人は**重複作成されません**（2回押しても安全）
5. 人物詳細には `守成 青山デイライト 260908` のように「イベント名 YYMMDD」で表示されます（内部の保存は `2026-09-08` 形式）
6. 検索画面のイベント名チップ／イベント名欄で「そのイベントで会った人」を後から検索できます

### SNS 確認（候補は確定するまで保存されません）

1. 人物詳細 または 新着リストの「SNS」から SNS確認画面へ
2. **公式サイトから検出**: 名刺の会社 URL のページ内にある Facebook / Instagram / LinkedIn / X / YouTube リンクを候補表示。
   本人のものと確認できたら「このアカウントで確定」。会社公式・店舗アカウントの可能性があるので必ず目で確認してください
3. **手動で登録**: プロフィール URL（`https://` 必須。各 SNS のドメインのみ受け付け）を貼って「確定」
4. **検索して探す**: 「氏名 会社名」を入れた Google 検索／各 SNS 内検索を新しいタブで開き、見つかった URL を手動登録
5. 確定済みは人物詳細にボタン表示（タップで開く）。「解除」で消せます。1 つでも確定すると「SNS確認済み」バッジが付きます
6. 探しても見つからなかった人は「候補なしで確認済みにする」で確認済みにできます（URL は保存されません）

### 名刺画像（2026-09 追加）

- スキャン取込時に、表面（PDF は2ページ目があれば裏面も）の縮小画像（長辺1200px と 320px の JPEG）を GAS に送り、**Google Drive の非公開フォルダ `meishi-images`**（スクリプトオーナーのマイドライブ。共有設定はしません）に保存します。名刺DB には Drive の fileId だけが入り、画像本体・URL は GitHub にもシートにも置きません
- 画像は検索画面の **人物詳細と整理モード** でサムネ表示され、タップで拡大（ピンチズーム可）。表示は GAS の認証付き action `cardImage` 経由のみで、ログインしていない人は取得できません
- 画像が無い人物（Eight 取込など）は画像枠が出ません。画像保存に失敗してもカード登録自体は従来どおり行われます
- **初回だけ**: GAS エディタで `setupImageFolder_` を実行し、Drive 権限の承認をしてください（appsscript.json に Drive スコープを追加したため、再承認が求められます）
- **既存のスキャン名刺に画像を後付け（バックフィル）**:
  ```
  cd /d X:\projects\meishi-search\ingest
  .venv\Scripts\python.exe ingest.py --backfill --dry-run   REM 対象件数と紐付け可能な件数を表示（送信しない）
  .venv\Scripts\python.exe ingest.py --backfill             REM 本実行（E:\namecardscan\done\** と error\ から元ファイルを探して登録）
  ```

### 初期表示について

ログイン直後の画面（入口の件数・検索条件・新着一覧）は `bootstrap` 1回で取得し、GAS 側で 120 秒キャッシュします。
保存・一括設定などの書き込みを行うとキャッシュは即座に消えるので、整理直後に古い件数が出ることはありません。
別端末やスプレッドシート直接編集の反映は最大 2 分遅れることがあります（新着画面の期間チップを押し直すと最新を取得します）。

### スプレッドシート側の注意

- `名刺DB` の既存列は変更していません。末尾に `importBatchId` が追加されます
- `人物管理` と `接触履歴` は初回の列セットアップ（`setupSnsBulkColumns_`）で自動作成されます。列を削除・並べ替えしないでください

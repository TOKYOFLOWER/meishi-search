# 第1部：名刺人脈検索システム ― CRM化 第1段階

現在動作している「名刺検索システム」を壊さず、次の段階として「人物詳細・接触履歴・フォロー管理・タグ管理」ができる人脈CRMへ拡張する。

## 実際の運用フロー

交流会当日にリアルタイム入力する用途ではない。

1. 守成クラブ等で名刺交換
2. 数日以内に名刺をまとめてスキャン
3. Eight等からCSV出力
4. CSVを名刺DBへ取り込み
5. 新しく追加された人物をUIで確認
6. 必要な人物にタグ・メモ・ニーズ・次回アクション等を付与
7. 後日の検索・フォロー・紹介・営業活動に活用

「名刺交換直後の現場入力」より「取込後の整理を効率化するUI」を優先する。

## 最重要追加機能

新しくDBに入った人物を簡単に見つけて整理できること。

## 「新着名刺」機能

トップまたは検索画面に `新着名刺` を追加。対象は最近取り込まれた人物（既存の `取込日` を利用）。
期間: 今日／過去3日／過去7日／過去30日 を選べる。デフォルトは過去7日。

## 新着整理モード

新しく取り込んだ名刺を順番に確認・整理できる画面。

```
新着名刺 42件   1 / 42
田中 太郎 / 株式会社ABC / 代表取締役
[重要度] [関係性] [タグ] [相手のニーズ] [次回アクション] [人物メモ]
保存して次へ →
```

目的: スキャン後に30〜100枚程度の名刺をまとめて短時間で整理する。

## 操作数を少なくする

必須入力は作らない。何も入力せず `次へ` だけでも進める。必要な人だけ情報を追加できる設計。

## クイックタグ（1タップ・複数選択可・自由追加可）

守成クラブ／経営者／要フォロー／花需要／法人ギフト／EC／IT／AI／業務効率化／販売代理店候補／協業候補／紹介者

## 後で整理

新着名刺一覧に `未整理` 状態を持たせる。人物管理レコードが存在しない、または整理済みフラグが false の人物を未整理として扱う。
人物管理シートに `organized`（boolean）列を追加してよい。

## 整理済み

人物情報を保存した際 `organized = true` にする。または `整理済みにする` ボタンを用意。
新着整理画面では「未整理のみ表示」と「全件表示」を切り替えられる。

## 接触履歴

名刺取込後に過去の接触として登録する運用。人物詳細画面から `接触履歴を追加`。
入力項目: 接触日／イベント名／接触種類／会話メモ／要フォロー／フォロー日。
接触日の初期値は今日でよいが、実際の交流会開催日に変更しやすくする。

## イベント名の再利用・整理セッション

新着整理モード開始時に `今回の名刺交換日` `イベント名` を任意で設定でき、その整理セッション中は
新規接触履歴の初期値として引き継ぐ（ブラウザ内の一時状態でよい）。

## 人物詳細

- 名刺情報: 氏名／会社名／役職／電話／メール／住所／Web／名刺交換日／取込日
- CRM情報: 重要度／関係性／タグ／相手のニーズ／紹介できる人／紹介してほしい人／次回アクション／次回アクション日／人物メモ
- 履歴: 接触履歴を新しい順で表示

## トップ画面改善

トップに 新着名刺／未整理／要フォロー／通常検索 の入口。最低限「新着名刺」「未整理」は実装。

## 優先順位

1. 新規取込された名刺が分かる 2. 未整理の人物が分かる 3. 連続して整理できる 4. 人物詳細を編集できる
5. タグを簡単に付けられる 6. 次回アクションを設定できる 7. 接触履歴を登録できる

## 削除する要件

`今日会った` クイック操作は実装しない（名刺交換直後は未登録で検索できないため）。

## 完成イメージ

交流会 → 名刺100枚 → まとめてスキャン → DB取込 → 「新着名刺 87件」→「未整理 87件」→ 順番に確認 →
重要人物だけタグ・メモ・フォロー設定 → 未整理 0件 → 後日検索・フォロー・紹介に活用。
スマートフォンでもストレスなく使える状態を第1段階の完成形とする。

# 第2部：追加要件 ― SNSアカウント確認＋名刺交換情報の一括登録

## 1. SNSアカウント管理

対象SNS: Facebook／Instagram／LinkedIn／X／YouTube／その他。
人物管理シートに追加: facebookUrl, instagramUrl, linkedinUrl, xUrl, youtubeUrl, otherSnsUrl, snsCheckedAt。

### SNSを探すために利用する名刺情報

氏名／会社名／役職／会社URL／メールアドレスのドメイン／所在地。特に `氏名 + 会社名` を基本検索キーとする。
例: 「田中太郎 株式会社ABC Facebook」。

### SNS候補検索

人物詳細画面に `SNSを探す` ボタン → SNS確認画面。Facebook／Instagram／LinkedIn／X それぞれ候補検索できる。

### 自動検出：会社Webサイト

名刺に会社URLがある場合、会社Webサイト内の facebook.com / instagram.com / linkedin.com / x.com / twitter.com / youtube.com
へのリンクを「公式サイトから検出」として候補表示する（検出元を表示）。

### SNS候補は自動確定しない（重要）

「候補」と「確認済み」を区別し、ユーザーが `このアカウントで確定` を押したものだけ人物情報として保存する。
（同姓同名・会社公式・店舗・本人個人アカウントの取り違え防止）

### SNS検索ショートカット

Facebookを検索／Instagramを検索／LinkedInを検索／Xを検索。押すと 氏名＋会社名 を検索語に入れた検索画面を開く。
利用者が候補を確認し、URLを人物詳細へ保存できる。

### SNS表示

確定済みSNSは人物詳細にアイコン／ボタン表示（タップでプロフィールを開く）。検索結果カードではSNSアイコンを大量表示しない。

### SNS確認状況

人物詳細に「SNS未確認」「SNS確認済み」表示（snsCheckedAt があれば確認済み）。新着整理画面からSNS確認へ移動できる。

## 2. 名刺交換日・イベントの一括設定

同じ守成クラブ等で一度に50〜100枚程度交換するため、人物ごとに交換日・イベント名を入力してはいけない。必ず一括設定できるようにする。

### 一括設定画面

新着名刺画面に `交換情報を一括設定` ボタン。対象は今回取り込んだ新着名刺。入力: 名刺交換日（例 2026/09/08）、イベント名（例 守成 青山デイライト）。

### 表示名

`守成 青山デイライト 260908` のように「イベント名 YYMMDD」を自動生成。DB内部では必ず正式な日付 `2026-09-08` で保持し、表示時のみ YYMMDD へ変換する。

### 一括設定対象

今回取り込んだ全件／未設定の名刺のみ／チェックした人物だけ。実行前に「87件に設定します」など対象件数を確認できる。

### データ保存方法

名刺交換日は既存の `名刺DB.名刺交換日` を利用。既に値がある場合は原則上書きしない。上書きする場合は確認を入れる。

### イベント名

名刺交換イベントは接触履歴として管理。一括設定した人数分の履歴を生成:
contactDate=2026/09/08、eventName=守成 青山デイライト、contactType=名刺交換、memo=空欄。
後から「守成 青山デイライトで会った人」を検索できる。

### 重複防止

一括設定を誤って2回実行しても、同じ人物について contactId／contactDate／eventName／contactType が同一の接触履歴を重複生成しない。

### イベント名の再利用

過去に入力したイベント名を候補表示する（入力履歴から候補を出す程度でよい。イベントマスタは不要）。

### 新着整理画面との連携

名刺をスキャン → Eight CSV取込 → 新着名刺 87件 → 交換情報を一括設定 → 2026/09/08 守成 青山デイライト → 87件に適用 →
人物を順番に確認 → 必要な人だけタグ・メモ・SNS確認 → 整理済み。

### 検索への追加

検索条件に `イベント` を追加。イベント名で検索するとそのイベントの接触履歴を持つ人物を一覧表示。日付で絞れる内部設計にしておく。

### UX上の重要事項

100件を整理する前提なので、1件ずつイベント日を入力する設計は禁止。一括入力を最優先。
SNSは全員について必ず探させるのではなく重要人物だけ確認できるようにする。新着整理画面では SNS確認 を任意操作として扱う。

### 今回の完成イメージ

```
新着名刺 87件
交換情報： 守成 青山デイライト 260908
↓ 人物詳細
田中 太郎 / 株式会社ABC / 代表取締役
交換： 守成 青山デイライト 260908
タグ： 経営者 / AI / 要フォロー
SNS： Facebook ✓  Instagram ✓  LinkedIn 未確認
↓ 必要に応じてSNS確認・メモ・フォロー設定
```
